# Security policy

Do not open public issues for suspected vulnerabilities. Report privately to security@yinne.dev or the repository private security advisory form. A monitored channel must exist before public release.

Include affected version, impact, reproduction, and sanitized evidence. Do not access other tenants, move real funds, exfiltrate data, or degrade service. Maintainers target acknowledgement within 72 hours and coordinate remediation/disclosure by severity.

Only versions identified in release notes are supported. Never send API keys, session/provider secrets, raw webhook bodies, PAN, or CVV. Yinne is infrastructure and does not guarantee deployment compliance.
